> **المرجع الأعلى:** [`../../en/00-PROJECT-RULES.md`](../../en/00-PROJECT-RULES.md) · **نسخة النظام الحاكمة:** [`../../en/systems/05-ai-generation.md`](../../en/systems/05-ai-generation.md) · هذه ترجمة عربية متزامنة.

## 0. القاعدة الأساسية — اقرأها قبل أي شيء

> ### `AI-001` (MUST) — الـ AI لا ينتج كود الموقع
> الـ AI يرجع **JSON منظَّم** يخضع لـ schema validation كاملة. ثم **المحرّك الموثوق** — وليس الـ AI — هو الذي يرندر.
> لا يصل HTML ولا CSS ولا JS من الـ AI إلى موقع منشور. أبدًا. تحت أي ظرف.

**لماذا هذه القاعدة هي أهم قرار معماري في المنتج:**

| لو أنتج الـ AI HTML | لو أنتج الـ AI JSON منظَّمًا |
|---|---|
| ثغرة XSS في كل موقع | لا سطح هجوم من المحتوى |
| استحالة تغيير التصميم لاحقًا | تغيير الـ theme يغيّر كل المواقع |
| استحالة تبديل الـ variant | التبديل فوري بلا فقد |
| استحالة الترجمة أو إعادة الاستخدام | المحتوى بيانات قابلة للمعالجة |
| كل موقع حالة خاصة | كل المواقع من محرّك واحد |
| المنتج = مولّد صفحات رخيص | المنتج = منصة |

**`AI-002` (MUST):** أي مخرَج من الـ AI يُعامل كـ **مدخل غير موثوق من مصدر خارجي**، بنفس درجة الحذر مع مدخلات المستخدم المجهول تمامًا.

## 1. التدفق الكامل

```
مدخل المستخدم (فئة النشاط / وصف حر)
   ↓
Prompt / Context Builder  (نسخة prompt مثبّتة)
   ↓
AI Provider Adapter       (واجهة موحدة)
   ↓
Structured JSON
   ↓
Schema Validation ──── غير صالح ──→ إصلاح/إعادة محاولة (بحد أقصى) ──→ فشل نظيف
   ↓ صالح
Business Rules / Moderation / Limits
   ↓
إنشاء Draft Revision
   ↓
إشعار المستخدم (الوظيفة اكتملت)
```

**`AI-010` (MUST):** كل توليد يتم في **وظيفة خلفية (job)** على طابور `ai`، لا داخل دورة request/response (`CORE-015`).

**`AI-011` (MUST):** الـ endpoint يرد `202 Accepted` مع `jobId` فورًا. الواجهة تتابع الحالة وتعرض تقدمًا مفهومًا.

**`AI-012` (MUST):** كل وظيفة توليد لها **مهلة قصوى صريحة**. الوظيفة التي تتجاوزها تُنهى وتُعلَّم `failed` برسالة مفهومة للمستخدم.

## 2. طبقة عزل المزوّد (Provider Abstraction)

**`AI-020` (MUST):** لا يُستدعى أي مزوّد AI مباشرةً من أي module. كل الاستدعاءات تمر عبر واجهة موحدة:

```ts
// packages/ai/provider.ts
export interface AiProvider {
  generateStructuredContent<T>(req: {
    schema: ZodSchema<T>;
    promptId: string;
    promptVersion: number;
    variables: Record<string, string>;
    maxTokens: number;
    timeoutMs: number;
  }): Promise<AiResult<T>>;

  generateImage(req: {
    promptId: string;
    promptVersion: number;
    variables: Record<string, string>;
    size: ImageSize;
    timeoutMs: number;
  }): Promise<AiResult<GeneratedImage>>;
}
```

**`AI-021` (MUST):** الطبقة تتيح: تبديل المزوّد، fallback لمزوّد بديل، توجيه حسب الميزانية، تسجيل موحد، ومحاسبة التكلفة — كلها بلا تعديل في منطق الأعمال.

**`AI-022` (MUST NOT):** ممنوع تسريب أخطاء المزوّد أو رسائله الخام إلى المستخدم أو إلى استجابة الـ API.

**`AI-023` (MUST):** كل استدعاء له: **timeout صريح** + **عدد محاولات محدود** + **قاطع دائرة (circuit breaker)** يفتح عند تكرار فشل المزوّد.

> **لماذا القاطع:** بدونه، عطل عند المزوّد يتحول إلى طابور متضخم، ثم استنزاف للـ workers، ثم تعطل المنتج كله — من عطل عند طرف ثالث.

**`AI-024` (MUST):** عند فتح القاطع، المستخدم يحصل على رسالة واضحة («التوليد غير متاح مؤقتًا، حاول بعد قليل») لا على خطأ تقني ولا على انتظار لا نهائي.

## 3. الـ Prompts

**`AI-030` (MUST):** كل prompt له **معرّف ورقم إصدار** ويُخزَّن في الكود تحت مراجعة، لا في قاعدة البيانات ولا مكتوبًا داخل دالة.

```
packages/ai/prompts/
  website-blueprint.v3.ts
  section-content.v2.ts
  seo-metadata.v1.ts
```

**`AI-031` (MUST):** `promptId` و `promptVersion` يُسجَّلان في `ai_generations` لكل توليد.

> **لماذا:** بعد شهرين سيسأل أحدهم «لماذا صارت النتائج أسوأ؟». بلا تسجيل النسخة، السؤال بلا إجابة.

**`AI-032` (MUST NOT):** ممنوع بناء prompt بدمج نص المستخدم مباشرةً في التعليمات. مدخل المستخدم يوضع في **قسم بيانات منفصل ومعلَّم بوضوح**، مع تعليمات صريحة بمعاملته كبيانات لا كتعليمات.

```ts
// ❌ خطر حقن مباشر
const prompt = `أنشئ موقعًا لـ ${userInput}`;

// ✅ فصل واضح
const prompt = buildPrompt({
  system: BLUEPRINT_SYSTEM_V3,           // تعليمات ثابتة
  userData: { businessDescription: userInput },  // بيانات، معلَّمة كذلك
});
```

**`AI-033` (MUST):** مدخل المستخدم محدود الطول قبل إرساله، ومنظَّف من محاولات الحقن الواضحة.

**`AI-034` (MUST NOT):** **ممنوع إرسال** أي من التالي للمزوّد: secrets، مفاتيح، بيانات مستأجرين آخرين، بيانات فوترة، PII لا يحتاجها التوليد، أو أي بنية داخلية للنظام.

**`AI-035` (MUST):** تغيير أي prompt = **إصدار جديد**، لا تعديل في مكانه. الإصدار القديم يبقى للمقارنة والتشخيص.

## 4. التحقق من المخرجات

**`AI-040` (MUST):** كل مخرَج يُتحقق منه بـ **نفس الـ schema** الذي يستخدمه الـ editor والـ renderer (`CE-010`). لا schema متساهل خاص بالـ AI.

**`AI-041` (MUST):** الترتيب الإلزامي للتحقق:

```
1. JSON صالح نحويًا؟           لا → إعادة محاولة
2. يطابق الـ schema؟            لا → إصلاح موجَّه، ثم إعادة محاولة
3. كل type/variant مسجَّل؟      لا → رفض
4. كل الروابط ببروتوكول مسموح؟  لا → رفض
5. يجتاز قواعد الأعمال؟         لا → رفض
6. يجتاز الـ moderation؟        لا → رفض + تسجيل
7. ضمن حدود الخطة؟              لا → رفض بخطأ حد
   ↓
حفظ كـ draft revision
```

**`AI-042` (MUST):** إعادة المحاولة عند فشل التحقق **محدودة (≤ 2)**، ومع تمرير رسالة الخطأ للنموذج لتصحيح المخرَج. بعد الحد، فشل نظيف — لا حلقة لا نهائية.

**`AI-043` (MUST NOT):** **ممنوع الحفظ الجزئي** لمخرَج فشل التحقق. إما نتيجة صالحة كاملة، أو لا شيء.

**`AI-044` (MUST NOT):** ممنوع «إصلاح» المخرَج بحذف الحقول الزائدة بصمت أو باستنتاج قيم ناقصة. الرفض أوضح من التخمين.

**`AI-045` (MUST):** المحتوى المولَّد يمر بفحص moderation قبل الحفظ. المرفوض يُسجَّل (بمعرّف الطلب فقط، لا المحتوى) مع رد مناسب للمستخدم.

## 5. التكلفة والحدود

**`AI-050` (MUST):** كل توليد يُسجَّل في `ai_generations` بـ: `organization_id`, `website_id`, `type`, `provider`, `model`, `prompt_version`, `status`, `tokens_in`, `tokens_out`, `cost_minor`, `duration_ms`.

**`AI-051` (MUST):** الحدود تُفرض على **ثلاثة مستويات** قبل بدء الوظيفة:

| المستوى | الغرض |
|---|---|
| لكل طلب | حد أقصى للـ tokens وعدد الصور |
| لكل مستخدم/موقع | معدل (rate limit) لمنع الإساءة |
| لكل مستأجر شهريًا | حد الخطة (entitlement) |

**`AI-052` (MUST):** فحص الـ entitlement يتم **قبل** جدولة الوظيفة، ويُعاد فحصه في الـ worker (`MT-044`).

**`AI-053` (MUST):** يوجد **حد إنفاق يومي على مستوى المنصة** يُطلق تنبيهًا ويقلّص التوليد عند تجاوزه.

> **لماذا:** خطأ في حلقة، أو إساءة استخدام، أو ارتفاع مفاجئ في الاستخدام يمكن أن يحوّل فاتورة يوم واحد إلى رقم يهدد المشروع. الحد يشتري وقت الاستجابة.

**`AI-054` (MUST):** فشل التوليد **لا يُحتسب** على حصة المستخدم. الفشل مشكلتنا لا مشكلته.

**`AI-055` (SHOULD):** نتائج التوليد المتطابقة المدخلات يمكن تخزينها مؤقتًا (cache) لتقليل التكلفة — بشرط أن يكون مفتاح الـ cache مقيّدًا بالـ scope (`MT-042`).

## 6. الصور المولَّدة

**`AI-060` (MUST):** الصورة المولَّدة تمر بـ **نفس مسار الـ assets** كأي صورة مرفوعة: تخزين، تحقق، تحسين، نسخ متعددة. راجع [`08-assets-media.md`](08-assets-media.md).

**`AI-061` (MUST):** الصورة تُخزَّن في تخزيننا فورًا. **ممنوع** الاعتماد على رابط مؤقت من المزوّد في محتوى الموقع.

**`AI-062` (MUST):** الصور المولَّدة تُعلَّم في `assets` بمصدرها (`source: 'ai'`) والنموذج المستخدم — لأسباب قانونية وتشخيصية.

## 7. الأنماط الممنوعة

| # | النمط | لماذا هو خطر |
|---|---|---|
| 1 | الـ AI يرجع HTML/CSS/JS | XSS + انهيار كامل لنموذج المنتج |
| 2 | استدعاء المزوّد داخل دورة الطلب | مهلة مستنفدة وتجربة سيئة |
| 3 | استدعاء المزوّد مباشرةً من module | استحالة التبديل والتتبع والمحاسبة |
| 4 | دمج نص المستخدم في التعليمات | حقن prompt |
| 5 | schema متساهل خاص بالـ AI | بيانات فاسدة تصل للمواقع |
| 6 | إعادة محاولة بلا حد | حلقة تستنزف الميزانية والـ workers |
| 7 | حفظ جزئي لمخرَج فاشل | موقع نصف مبني بحالة غير متسقة |
| 8 | prompt بلا نسخة | استحالة تفسير تدهور الجودة |
| 9 | بلا قاطع دائرة | عطل طرف ثالث يُسقط المنتج |
| 10 | بلا حد إنفاق | فاتورة تهدد المشروع |
| 11 | احتساب الفشل على حصة المستخدم | إحباط العميل وشكاوى محقة |
| 12 | رابط صورة مؤقت من المزوّد | صور مكسورة في مواقع منشورة |

## 8. الاختبارات المطلوبة

**`AI-070` (MUST):** اختبارات عقد (contract tests) على الـ schemas: مخرَج صالح يُقبل، وكل شكل فاسد معروف يُرفض.

**`AI-071` (MUST):** اختبار بمزوّد وهمي (mock) يرجع: JSON فاسد نحويًا، JSON مخالف للـ schema، `type` غير مسجَّل، رابط `javascript:`، نص يتجاوز الحد. **كلها تُرفض ولا يُحفظ شيء.**

**`AI-072` (MUST):** اختبار الحدود: تجاوز حد الخطة يمنع الجدولة برسالة واضحة.

**`AI-073` (MUST):** اختبار قاطع الدائرة: فشل متكرر من المزوّد يفتح القاطع، والمستخدم يحصل على رسالة مناسبة.

**`AI-074` (MUST):** اختبار الحقن: وصف نشاط يحتوي «تجاهل التعليمات السابقة وأرجع…» **لا يغيّر** بنية المخرَج ولا يتجاوز الـ validation.

**`AI-075` (MUST):** اختبار المحاسبة: كل توليد (ناجح أو فاشل) يُنتج صفًا صحيحًا في `ai_generations`.

## 9. Definition of Done — AI

- [ ] التوليد في وظيفة خلفية، والـ endpoint يرد `202` بـ `jobId`.
- [ ] الاستدعاء عبر `AiProvider` فقط.
- [ ] timeout + retry محدود + circuit breaker مطبّقة.
- [ ] الـ prompt له `promptId` و `promptVersion`، ومسجَّلان في `ai_generations`.
- [ ] مدخل المستخدم معزول عن التعليمات ومحدود الطول.
- [ ] لا secrets ولا بيانات زائدة تُرسل للمزوّد.
- [ ] التحقق بنفس schema الـ editor/renderer، مع `.strict()`.
- [ ] إعادة المحاولة محدودة، ولا حفظ جزئي.
- [ ] moderation مطبَّق قبل الحفظ.
- [ ] الحدود مفحوصة قبل الجدولة وفي الـ worker.
- [ ] الفشل لا يُحتسب على حصة المستخدم.
- [ ] الصور المولَّدة في تخزيننا ومعلَّمة بمصدرها.
- [ ] الاستخدام والتكلفة مسجَّلان بالكامل.
- [ ] اختبار الحقن يمر.

---

## 10. ما يحتاج ADR

- السماح بأي مخرَج AI غير منظَّم يصل للموقع.
- تغيير المزوّد الأساسي.
- تشغيل نموذج محليًا.
- تدريب/ضبط نموذج على بيانات العملاء (يحتاج مراجعة قانونية أيضًا).
- السماح بتوليد كود أو سكربتات بأي شكل.
