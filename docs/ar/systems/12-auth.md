# 12 — Authentication & Authorization

> **بادئة القواعد:** `AU-` · **الحالة:** إلزامي · **المالك:** Backend / Security
> **المرجع الأعلى:** [`../../en/00-PROJECT-RULES.md`](../../en/00-PROJECT-RULES.md) · **نسخة النظام الحاكمة:** [`../../en/systems/12-auth.md`](../../en/systems/12-auth.md) · هذه ترجمة عربية متزامنة.
> **يحقق المبدأ:** `CORE-016` (Least privilege)

---

## 0. الفرق الجوهري

| | السؤال | الفشل يعني |
|---|---|---|
| **Authentication** | من أنت؟ | انتحال هوية |
| **Authorization** | ما المسموح لك؟ | تجاوز صلاحيات |

الاثنان مطلوبان دائمًا. **المصادقة الصحيحة بلا تفويض صحيح تعني أن كل مستخدم مسجَّل يستطيع فعل كل شيء.**

---

## 1. المصادقة

**`AU-001` (MUST):** جلسات لوحة التحكم عبر **cookies** بالخصائص التالية إلزاميًا:

```
HttpOnly            ← يمنع قراءتها بـ JavaScript (حماية من سرقة الجلسة عبر XSS)
Secure              ← لا تُرسل إلا عبر HTTPS
SameSite=Lax (أو Strict)  ← حماية من CSRF
Path=/
Max-Age محدَّد صراحةً
```

**`AU-002` (MUST NOT):** **ممنوع** تخزين رمز الجلسة أو أي توكن طويل العمر في `localStorage` أو `sessionStorage`.

> **لماذا:** أي ثغرة XSS واحدة — في أي مكان في لوحة التحكم — تتحول فورًا إلى سرقة كاملة لجلسات كل المستخدمين. الـ cookie بخاصية `HttpOnly` لا يمكن لـ JavaScript قراءته أصلًا.

**`AU-003` (MUST):** كلمات المرور بـ **Argon2id** (أو bcrypt بمعامل كلفة مناسب). **ممنوع** MD5 أو SHA بأي شكل.

**`AU-004` (MUST):** الحد الأدنى لطول كلمة المرور **12 حرفًا**، مع فحص مقابل قوائم كلمات المرور المسرَّبة الشائعة. **ممنوع** فرض قواعد تعقيد عقيمة (رمز + رقم + حرف كبير) التي تنتج `P@ssw0rd1`.

**`AU-005` (MUST):** rate limiting صارم على: تسجيل الدخول، التسجيل، إعادة تعيين كلمة المرور، وإعادة إرسال التحقق — **لكل حساب ولكل IP معًا**.

**`AU-006` (MUST):** رسالة فشل تسجيل الدخول **موحّدة**: «البريد أو كلمة المرور غير صحيحة». **ممنوع** التمييز بين «الحساب غير موجود» و«كلمة المرور خاطئة».

> **لماذا:** التمييز يسمح بحصر الحسابات الموجودة (enumeration)، فيعرف المهاجم أي بريد مسجَّل عندنا ويركّز هجومه عليه.

**`AU-007` (MUST):** رموز إعادة تعيين كلمة المرور: **قصيرة العمر (≤ 60 دقيقة)**، **للاستخدام مرة واحدة**، عشوائية قويًا، ومُبطَلة عند الاستخدام أو عند تغيير كلمة المرور.

**`AU-008` (MUST):** طلب إعادة التعيين يرد **بنفس الرسالة** سواء وُجد البريد أم لا (نفس سبب `AU-006`).

**`AU-009` (MUST):** تغيير كلمة المرور أو البريد **يُبطل كل الجلسات الأخرى** ويُخطر المستخدم بالبريد.

**`AU-010` (MUST):** الجلسة لها **عمر أقصى مطلق** إضافة لعمر الخمول، وتُجدَّد دوريًا لا إلى ما لا نهاية.

**`AU-011` (MUST):** تسجيل الخروج يُبطل الجلسة **في الخادم**، لا بحذف الـ cookie من المتصفح فقط.

**`AU-012` (SHOULD):** MFA متاح للحسابات الحساسة، وإلزامي لأي حساب إداري داخلي.

## 2. التفويض — الأدوار

**`AU-020` (MUST):** الأدوار داخل الـ organization:

| الدور | الصلاحيات |
|---|---|
| **Owner** | كل شيء: الفوترة، حذف المستأجر، دعوة الأعضاء، نقل الملكية، تحكم كامل بالمواقع |
| **Admin** | إدارة المواقع والأعضاء — **بلا** نقل ملكية ولا حذف مستأجر ولا فوترة |
| **Editor** | تحرير ونشر المواقع المخوَّل لها حسب السياسة |
| **Viewer** | قراءة الـ analytics والـ leads حيث مُنح ذلك فقط |

**`AU-021` (MUST):** **Owner واحد على الأقل دائمًا.** ممنوع أن تصل المؤسسة لحالة بلا owner (بإزالة أو تخفيض آخر owner).

**`AU-022` (MUST):** نقل الملكية عملية صريحة بتأكيد من الطرفين، ومسجَّلة في `audit_logs`.

**`AU-023` (MUST NOT):** **ممنوع** أن يرفع المستخدم دوره أو دور غيره فوق دوره الحالي.

> **لماذا:** بلا هذه القاعدة، Admin واحد يرفع نفسه إلى Owner ويستولي على الحساب والفوترة.

**`AU-024` (MUST):** الدعوات: بريد + رمز عشوائي قصير العمر للاستخدام مرة واحدة، **مقيّد بعنوان البريد المدعو**.

**`AU-025` (MUST):** إزالة عضو **تُبطل جلساته** المتعلقة بتلك المؤسسة فورًا.

---

## 3. التفويض — الفرض

**`AU-030` (MUST):** الفحص **server-side على كل endpoint حساس** (`CORE-004`). إخفاء الزر ليس حماية.

**`AU-031` (MUST):** ترتيب الفحص الإلزامي على كل طلب:

```
1. مصادق؟              لا → 401
2. الجلسة صالحة ونشطة؟  لا → 401
3. عضو في المؤسسة؟      لا → 404 (ليس 403)
4. الدور كافٍ للفعل؟     لا → 403
5. المورد داخل الـ scope؟ لا → 404
6. الـ entitlement يسمح؟ لا → 403 مع تفاصيل الحد
```

**`AU-032` (MUST):** التمييز الدقيق بين `401` و `403` و `404`:

| الرمز | المعنى |
|---|---|
| `401` | غير مصادق أو الجلسة منتهية |
| `403` | مصادق، وينتمي للمؤسسة، لكن دوره لا يسمح بهذا الفعل |
| `404` | المورد غير موجود **أو** لا ينتمي لمستأجره (`MT-014`) |

**`AU-033` (MUST):** الافتراضي **المنع**. Endpoint بلا فحص صريح **يُرفض**، لا يُسمح به.

> **لماذا:** بالافتراض المفتوح، endpoint منسي يصبح ثغرة صامتة. بالافتراض المغلق، يصبح باقًا مرئيًا يُكتشف فورًا في الاختبار.

**`AU-034` (MUST):** الصلاحيات تُفحص على **الفعل والمورد معًا**، لا على الفعل وحده.

---

## 4. مفاتيح الـ API (عند إضافتها)

**`AU-040` (MUST):** المفتاح يُخزَّن **مجزَّأً (hashed)** كما تُخزَّن كلمات المرور. **ممنوع** تخزينه نصًا واضحًا.

**`AU-041` (MUST):** المفتاح يُعرض **مرة واحدة فقط** عند الإنشاء، ولا يمكن استرجاعه بعدها.

**`AU-042` (MUST):** لكل مفتاح: نطاق صلاحيات محدود، مؤسسة واحدة، تاريخ انتهاء اختياري، وتسجيل لآخر استخدام.

**`AU-043` (MUST):** إبطال المفتاح **فوري**.

**`AU-044` (MUST):** إنشاء المفاتيح وإبطالها واستخدامها لأول مرة — كلها في `audit_logs`.

---

## 5. الأمن حول الجلسة

**`AU-050` (MUST):** حماية CSRF لكل عملية تغيّر حالة في لوحة التحكم: `SameSite` + رمز CSRF أو فحص `Origin`/`Referer`.

**`AU-051` (MUST):** تثبيت الجلسة (session fixation) ممنوع: **معرّف جلسة جديد** عند كل تسجيل دخول ناجح.

**`AU-052` (MUST):** العمليات الحساسة (تغيير البريد، تغيير كلمة المرور، حذف المؤسسة، نقل الملكية، تغيير الفوترة) تتطلب **إعادة تأكيد كلمة المرور** لو مرّ وقت على المصادقة.

**`AU-053` (MUST):** إخطار بالبريد عند: تسجيل دخول من جهاز جديد، تغيير كلمة المرور، تغيير البريد، إضافة أو إزالة عضو، تغيير الفوترة.

**`AU-054` (MUST):** المستخدم يستطيع رؤية جلساته النشطة وإنهاء أي منها.

---

## 6. التسجيل والتدقيق

**`AU-060` (MUST NOT):** **ممنوع** تسجيل كلمات المرور أو الرموز أو مفاتيح الـ API أو ملفات الجلسة — حتى في بيئة التطوير، وحتى مجزَّأة جزئيًا.

**`AU-061` (MUST):** تُسجَّل في `audit_logs`: تسجيل الدخول الناجح والفاشل، تغيير كلمة المرور، تغيير البريد، تغييرات الأدوار، الدعوات، الإزالات، عمليات مفاتيح الـ API، نقل الملكية.

**`AU-062` (MUST):** محاولات تسجيل الدخول الفاشلة المتكررة **تُطلق تنبيهًا** عند تجاوز عتبة.

## 7. الأنماط الممنوعة

| # | النمط | لماذا هو خطر |
|---|---|---|
| 1 | التوكن في `localStorage` | أي XSS = سرقة كل الجلسات |
| 2 | رسالة خطأ تميّز الحساب الموجود | حصر الحسابات (enumeration) |
| 3 | `403` لمورد مستأجر آخر | تأكيد وجود المورد |
| 4 | الافتراضي «مسموح» | endpoint منسي = ثغرة صامتة |
| 5 | فحص الفعل بلا المورد | تعديل مورد لا يملكه |
| 6 | رفع الدور فوق الدور الحالي | استيلاء على الحساب |
| 7 | مفتاح API نصًا واضحًا | تسريب قاعدة البيانات = تسريب كل المفاتيح |
| 8 | رمز إعادة تعيين طويل العمر | نافذة هجوم واسعة |
| 9 | رمز إعادة تعيين قابل لإعادة الاستخدام | إعادة استيلاء بعد الاسترداد |
| 10 | بلا إبطال عند تغيير كلمة المرور | المهاجم يظل داخل الحساب |
| 11 | بلا معرّف جلسة جديد عند الدخول | تثبيت جلسة |
| 12 | بلا حماية CSRF | تنفيذ عمليات نيابة عن المستخدم |
| 13 | MD5/SHA لكلمات المرور | كسر فوري عند التسريب |
| 14 | قواعد تعقيد عقيمة | كلمات مرور أضعف عمليًا |

## 8. الاختبارات المطلوبة

**`AU-070` (MUST):** اختبار لكل دور × كل فعل: مسموح يُسمح، وممنوع يُرفض بالرمز الصحيح.

**`AU-071` (MUST):** اختبار تصعيد الصلاحيات: Admin يحاول رفع نفسه لـ Owner → مرفوض.

**`AU-072` (MUST):** اختبار عدم التمييز: بريد موجود وبريد غير موجود → **نفس الرسالة ونفس زمن الاستجابة تقريبًا**.

**`AU-073` (MUST):** اختبار رمز إعادة التعيين: استخدام مرتين → الثانية مرفوضة؛ بعد انتهاء الصلاحية → مرفوض.

**`AU-074` (MUST):** اختبار الإبطال: تغيير كلمة المرور → الجلسات الأخرى **لم تعد تعمل**.

**`AU-075` (MUST):** اختبار تثبيت الجلسة: معرّف الجلسة يتغير بعد تسجيل الدخول.

**`AU-076` (MUST):** اختبار CSRF: طلب تغيير حالة بلا رمز صالح → مرفوض.

**`AU-077` (MUST):** اختبار آخر owner: إزالة أو تخفيض آخر owner → مرفوض.

**`AU-078` (MUST):** اختبار الافتراضي المغلق: endpoint بلا حارس → يفشل الاختبار.

## 9. Definition of Done — Auth

- [ ] الجلسة في cookie بـ `HttpOnly` + `Secure` + `SameSite`.
- [ ] لا توكن في تخزين المتصفح.
- [ ] كلمات المرور بـ Argon2id/bcrypt بمعامل مناسب.
- [ ] حد أدنى 12 حرفًا + فحص القوائم المسرَّبة، بلا قواعد تعقيد عقيمة.
- [ ] Rate limit على كل مسارات المصادقة.
- [ ] رسائل موحّدة تمنع حصر الحسابات.
- [ ] رموز إعادة التعيين قصيرة ولمرة واحدة.
- [ ] تغيير كلمة المرور/البريد يبطل الجلسات الأخرى ويخطر المستخدم.
- [ ] معرّف جلسة جديد عند كل دخول.
- [ ] حماية CSRF لكل عملية تغيير حالة.
- [ ] ترتيب الفحص الست خطوات مطبَّق.
- [ ] `401`/`403`/`404` مستخدمة بدقة.
- [ ] الافتراضي المنع — لا endpoint بلا حارس.
- [ ] الفحص على الفعل والمورد معًا.
- [ ] Owner واحد على الأقل مضمون دائمًا.
- [ ] لا تسجيل لأي سر أو رمز.
- [ ] كل الأحداث الحساسة في `audit_logs`.

---

## 10. ما يحتاج ADR

- إضافة OAuth أو SSO أو SAML.
- تغيير آلية الجلسة (من cookies إلى JWT مثلًا).
- إضافة أدوار أو نموذج صلاحيات أدق (permission-based).
- السماح بمفاتيح API عابرة للمؤسسات.
- خفض أي متطلب أمني في هذا الملف.
