## 0. الغرض والنطاق

المحرّر هو **الواجهة التي يحكم بها المستخدم على المنتج كله**. تعقيده أو بطؤه أو فقدانه لتعديل واحد يكفي لفقد العميل، مهما كان الـ backend متقنًا.

**قاعدة حاكمة:** المحرّر **عميل غبي أمام عقد موثوق**. لا يحتوي منطق أعمال، ولا يقرر صلاحيات، ولا يكتب بيانات غير مُتحقق منها. كل ما يفعله: يعرض، يجمع التعديلات، ويرسلها لعقد يتحقق منها.

---

## 1. نموذج الحالة (State Model)

**`VE-001` (MUST):** حالة المحرّر موثَّقة صراحةً وتفصل بوضوح بين:

| الطبقة | ما هي | مثال |
|---|---|---|
| **Document** | محتوى الموقع الفعلي (يُحفظ) | pages, sections, theme |
| **Session** | حالة التحرير (لا تُحفظ) | العنصر المحدد، التبويب المفتوح، حالة الحفظ |
| **History** | سجل الأوامر للتراجع | آخر N أمر |
| **Server** | آخر نسخة مؤكدة من الخادم | `version`, `updatedAt` |

**`VE-002` (MUST NOT):** ممنوع خلط حالة الجلسة مع المستند. «العنصر المحدد» ليس جزءًا من محتوى الموقع ولا يُرسل للحفظ.

**`VE-003` (MUST):** كل تعديل يُمثَّل كـ **أمر (command)** له شكل معروف — لا تعديل مباشر عشوائي على الحالة.

```ts
type EditorCommand =
  | { kind: 'section.updateData';    sectionId: string; patch: Partial<SectionData> }
  | { kind: 'section.changeVariant'; sectionId: string; variant: string }
  | { kind: 'section.reorder';       sectionId: string; toIndex: number }
  | { kind: 'section.duplicate';     sectionId: string }
  | { kind: 'section.toggleVisible'; sectionId: string; visible: boolean }
  | { kind: 'section.delete';        sectionId: string }
  | { kind: 'section.insert';        type: string; variant: string; atIndex: number }
  | { kind: 'theme.updateTokens';    patch: Partial<ThemeTokens> }
  | { kind: 'page.updateMeta';       pageId: string; patch: Partial<PageMeta> };
```

> **لماذا الأوامر:** التراجع/الإعادة يصبح تافهًا، والحفظ التدريجي ممكنًا، والتتبع للتشخيص متاحًا، والاختبار مباشرًا.

**`VE-004` (MUST):** كل أمر **قابل للعكس** — إما بأمر معاكس أو بلقطة قبله.

## 2. المعاينة (Preview)

**`VE-010` (MUST):** المعاينة تعمل في **iframe أو سياق عرض معزول**. ممنوع رندر مكوّنات الموقع مباشرةً داخل شجرة DOM الخاصة بلوحة التحكم.

> **لماذا:** بلا عزل، يتسرب CSS لوحة التحكم إلى الموقع والعكس. المستخدم يرى معاينة لا تشبه الموقع الحقيقي — وهذا يقتل الثقة في المنتج.

**`VE-011` (MUST):** المعاينة تستخدم **نفس مكوّنات `packages/site-sections`** التي يستخدمها الـ renderer العام. ممنوع نسخة "مبسّطة" للمحرّر.

**`VE-012` (MUST):** التواصل مع الـ iframe عبر `postMessage` برسائل معرّفة النوع، مع **التحقق من `origin`** في كل رسالة واردة.

**`VE-013` (MUST):** معاينة الأجهزة (ديسكتوب/تابلت/موبايل) تغيّر **عرض الإطار** فقط. ممنوع الادعاء بأن المعاينة تساوي كل متصفح فعلًا.

**`VE-014` (MUST):** المعاينة تعكس **اتجاه ولغة الموقع** (RTL/LTR)، لا اتجاه لوحة التحكم. راجع [`23-i18n-rtl.md`](23-i18n-rtl.md).

## 3. الحفظ التلقائي (Autosave) والتزامن

هذا أكثر جزء يُخطئ فيه بناة المحررات. القواعد التالية تمنع **الفقد الصامت للتعديلات** — أسوأ باق ممكن في منتج كهذا.

**`VE-020` (MUST):** الحفظ التلقائي **debounced** (600–1500ms بعد آخر تعديل)، وبحد أقصى للتكرار حتى أثناء الكتابة المستمرة.

**`VE-021` (MUST):** كل طلب حفظ يرسل **رقم النسخة المتوقع** (`expectedVersion`).

```http
PATCH /api/v1/websites/{websiteId}/draft
{
  "expectedVersion": 42,
  "commands": [ ... ]
}
```

**`VE-022` (MUST):** الخادم يرد **`409 Conflict`** لو اختلفت النسخة، ومعه بيانات كافية للمصالحة:

```json
{
  "error": {
    "code": "REVISION_CONFLICT",
    "currentVersion": 45,
    "changedSections": ["sec_01J...", "sec_02K..."],
    "changedBy": { "userId": "usr_...", "at": "2026-09-15T10:12:00Z" }
  }
}
```

**`VE-023` (MUST NOT):** **ممنوع Last-Write-Wins الصامت.** الكتابة فوق تعديل شخص آخر بلا علمه هي فقد بيانات، لا "سلوك افتراضي".

**`VE-024` (MUST):** عند `409`، الواجهة **لا تفقد تعديلات المستخدم المحلية**. تعرض حالة تعارض واضحة مع خيارات صريحة (إعادة التحميل / الاحتفاظ بتعديلاتي / عرض الفروق).

**`VE-025` (MUST):** الواجهة **تفاؤلية (optimistic)**: التعديل يظهر فورًا. عند فشل الحفظ، تتراجع بوضوح مع رسالة مفهومة — لا فشل صامت.

**`VE-026` (MUST):** حالة الحفظ ظاهرة دائمًا للمستخدم: `محفوظ` · `جارٍ الحفظ…` · `تعذّر الحفظ — إعادة المحاولة`.

**`VE-027` (MUST):** عند فقد الاتصال، المحرّر يحتفظ بالتعديلات محليًا ويعيد المحاولة بتراجع أسّي عند العودة. محاولة مغادرة الصفحة بتعديلات غير محفوظة **تُحذَّر صراحةً**.

**`VE-028` (MUST):** الحفظ التلقائي يكتب في **الـ draft revision فقط**. ممنوع منعًا باتًا أن يمس النسخة المنشورة. راجع [`06-renderer-publishing.md`](06-renderer-publishing.md).

## 4. التراجع والإعادة (Undo/Redo)

**`VE-030` (MUST):** التراجع/الإعادة من **سجل الأوامر في الواجهة**، لا برحلة للخادم عند كل ضغطة.

**`VE-031` (MUST):** عمق السجل **≥ 50 أمرًا**، ويُمسح عند إعادة تحميل الصفحة (مع توضيح ذلك للمستخدم ضمنيًا بالسلوك المتوقع).

**`VE-032` (MUST):** الخادم يحفظ **نقاط تفتيش دورية (checkpoints)** للـ draft، تسمح بالعودة لنقطة سابقة بعد إغلاق الجلسة.

**`VE-033` (MUST):** الحذف عملية قابلة للتراجع خلال الجلسة. حذف section لا يُفقد محتواه فورًا.

---

## 5. أوامر الـ Section في الواجهة

**`VE-040` (MUST):** الأوامر المتاحة على كل section: تغيير الـ variant · تكرار · إخفاء/إظهار · حذف · إعدادات · نقل لأعلى/لأسفل.

**`VE-041` (MUST):** تغيير الـ variant **لا يفقد أي بيانات** (`CE-004`). لو حاول المستخدم تغيير variant وضاع محتوى — فهذا باق في المحرّك، لا في المحرّر.

**`VE-042` (MUST):** إعادة الترتيب بالسحب والإفلات، مع **بديل بلوحة المفاتيح إلزامي** (أزرار لأعلى/لأسفل أو اختصارات). السحب والإفلات وحده ليس واجهة مقبولة.

**`VE-043` (MUST):** إضافة section تعرض **معرض الـ variants بصور المعاينة** من السجل (`CE-053`)، لا قائمة أسماء نصية.

**`VE-044` (MUST):** الإخفاء يُخزَّن في `settings.visibility` ولا يحذف البيانات.

---

## 6. التحرير النصي والمدخلات

**`VE-050` (MUST):** التحرير النصي المباشر (inline) يكتب **نصًا عاديًا** في الحقل المقابل. ممنوع أن ينتج المحرّر HTML (`CE-002`).

**`VE-051` (MUST):** اللصق من Word أو صفحة ويب **يُنظَّف فورًا** إلى نص عادي (أو التمثيل المنظَّم المعتمد). ممنوع تسرب `<span style=...>` إلى البيانات.

**`VE-052` (MUST):** حدود الطول من الـ schema تُطبَّق في الواجهة **وتُعرض للمستخدم** (عدّاد أو تحذير) قبل رفض الخادم.

> الواجهة تمنع بلطف؛ الخادم يرفض بحزم. الاثنان مطلوبان (`CORE-005`).

**`VE-053` (MUST):** رفع الصور من المحرّر يمر بمسار الـ assets المعتمد: signed upload + معالجة خلفية. راجع [`08-assets-media.md`](08-assets-media.md).

**`VE-054` (MUST):** حقل `alt` للصورة **مطلوب بوضوح** في الواجهة مع شرح سبب أهميته، لا حقلًا اختياريًا مدفونًا.

---

## 7. الحدود والصلاحيات في الواجهة

**`VE-060` (MUST):** الواجهة تقرأ الـ entitlements وتُعطّل ما لا تسمح به الخطة **مع رسالة واضحة وطريق للترقية** — لا زر يفشل بصمت. راجع [`11-billing-entitlements.md`](11-billing-entitlements.md).

**`VE-061` (MUST NOT):** **إخفاء أو تعطيل زر ليس حماية** (`CORE-004`). الخادم يفرض كل حد وكل صلاحية مستقلًا تمامًا عن الواجهة.

**`VE-062` (MUST):** حدود الاستخدام (عدد الصفحات، الأقسام، توليدات الـ AI) تظهر للمستخدم **قبل** بلوغ الحد، لا بعد الفشل.

---

## 8. الأداء وتجربة الاستخدام

**`VE-070` (MUST):** المحرّر يظل مستجيبًا مع **≥ 40 section في صفحة واحدة**. الرندر المتكرر للشجرة كلها عند كل ضغطة زر غير مقبول.

**`VE-071` (MUST):** تحديث المعاينة أثناء الكتابة **مقيَّد (throttled)** ولا يعيد تحميل الـ iframe بالكامل عند كل حرف.

**`VE-072` (MUST):** كل شاشة أساسية لها حالات: تحميل، فراغ، خطأ — معرّفة ومصمّمة (`CORE-DoD`).

**`VE-073` (MUST):** الوصولية الأساسية: تنقل كامل بلوحة المفاتيح، تسميات (labels) واضحة، إدارة صحيحة للـ focus في النوافذ المنبثقة.

## 9. الأنماط الممنوعة

| # | النمط | لماذا هو خطر |
|---|---|---|
| 1 | Last-Write-Wins بلا نسخة | فقد صامت لعمل المستخدم — أسوأ باق ممكن |
| 2 | رندر الموقع داخل DOM لوحة التحكم | تسرب CSS ومعاينة كاذبة |
| 3 | مكوّنات "مبسّطة" للمعاينة | المعاينة لا تطابق النتيجة |
| 4 | الحفظ التلقائي يمس النسخة المنشورة | تعديلات نصف مكتملة تظهر للزوار |
| 5 | إنتاج HTML من التحرير النصي | كسر `CE-002` + XSS |
| 6 | اللصق بلا تنظيف | تلوث البيانات بستايلات Word |
| 7 | السحب والإفلات كوسيلة وحيدة | استبعاد مستخدمي لوحة المفاتيح |
| 8 | تعطيل زر كوسيلة فرض حد | الـ API مكشوف — تجاوز بسطر واحد |
| 9 | فشل حفظ صامت | المستخدم يعمل ساعة ثم يفقدها |
| 10 | `postMessage` بلا فحص `origin` | ثغرة حقن من نافذة أخرى |

## 10. الاختبارات المطلوبة

**`VE-080` (MUST):** اختبار لكل أمر: يطبّق الأثر الصحيح، ويتراجع بشكل صحيح.

**`VE-081` (MUST):** اختبار تعارض النسخ: محرّران، الأول يحفظ، الثاني يحصل على `409` **ولا يفقد تعديلاته المحلية**.

**`VE-082` (MUST):** اختبار تغيير الـ variant لكل نوع: لا فقد بيانات (يكمّل `CE-071`).

**`VE-083` (MUST):** اختبار الشبكة: فقد الاتصال أثناء الحفظ → إعادة محاولة → نجاح، بلا تكرار للتعديل وبلا فقد.

**`VE-084` (MUST):** اختبار E2E للمسار الكامل: إنشاء → تعديل نص → تغيير variant → رفع صورة → إعادة ترتيب → نشر → زيارة الموقع العام والتأكد من ظهور التعديلات.

**`VE-085` (MUST):** اختبار المحرّر في RTL و LTR معًا.

---

## 11. Definition of Done — Visual Editor

- [ ] كل تعديل جديد مُمثَّل كأمر معرَّف النوع وقابل للعكس.
- [ ] حالة الجلسة منفصلة عن المستند.
- [ ] الحفظ يرسل `expectedVersion` ويعالج `409` بلا فقد.
- [ ] حالة الحفظ ظاهرة للمستخدم دائمًا.
- [ ] المعاينة معزولة وتستخدم مكوّنات `site-sections` نفسها.
- [ ] `postMessage` يتحقق من `origin`.
- [ ] تغيير الـ variant بلا فقد بيانات.
- [ ] بديل لوحة مفاتيح لكل تفاعل بالسحب.
- [ ] الحدود تُعرض بوضوح، والخادم يفرضها مستقلًا.
- [ ] حالات التحميل/الفراغ/الخطأ معالَجة.
- [ ] مختبَر في RTL و LTR، وعلى موبايل وديسكتوب.
- [ ] اختبار E2E للمسار الكامل يمر.

---

## 12. ما يحتاج ADR

- التحرير التعاوني اللحظي (CRDT / OT).
- السماح بـ HTML أو CSS أو JS مخصص من المحرّر.
- تغيير نموذج التزامن (من optimistic + version إلى غيره).
- بناء محرّر بمكوّنات مختلفة عن `site-sections`.
