# 16 — Frontend Engineering Standards

> **بادئة القواعد:** `FE-` · **الحالة:** إلزامي · **المالك:** Frontend
> **المرجع الأعلى:** [`../../en/00-PROJECT-RULES.md`](../../en/00-PROJECT-RULES.md) · **نسخة النظام الحاكمة:** [`../../en/systems/16-frontend-standards.md`](../../en/systems/16-frontend-standards.md) · هذه ترجمة عربية متزامنة.

---

## 0. عالمان بصريان منفصلان

| | لوحة التحكم | مكوّنات المواقع |
|---|---|---|
| الحزمة | `packages/ui-dashboard` | `packages/site-sections` |
| يستهلكها | `apps/dashboard-web` | `apps/public-renderer` + معاينة المحرّر |
| الجمهور | مستخدم مسجَّل يعمل يوميًا | زائر مجهول يمر مرة |
| الأولوية | كثافة معلومات وكفاءة | سرعة تحميل وجمال |
| الستايل | Design System داخلي | Theme Tokens لكل موقع |

**`FE-001` (MUST NOT):** ممنوع الاستيراد بين الحزمتين في أي اتجاه (`CORE-021`).

> **لماذا:** خلطهما يعني أن تحسينًا في لوحة التحكم قد يغيّر شكل مواقع منشورة لعملاء — أو أن كود لوحة التحكم يُشحن لزوار كل موقع.

---

## 1. TypeScript

**`FE-010` (MUST):** `strict: true` في كل حزمة. ممنوع تعطيلها جزئيًا.

**`FE-011` (MUST NOT):** `any` ممنوع (`CORE-031`)، و `@ts-ignore` ممنوع (`CORE-032`).

**`FE-012` (MUST):** أنواع الـ API مشتقة من `packages/schemas`، لا مكتوبة يدويًا في الـ frontend.

> **لماذا:** النوع المكتوب يدويًا ينحرف عن الـ backend بصمت، فتنكسر الواجهة في الإنتاج بلا أي خطأ في الـ build.

**`FE-013` (MUST):** أنواع الـ props صريحة ومسماة `<ComponentName>Props`.

---

## 2. الحالة (State)

**`FE-020` (MUST):** فصل واضح بين ثلاثة أنواع من الحالة:

| النوع | الأداة المناسبة |
|---|---|
| حالة الخادم (بيانات من الـ API) | طبقة جلب بيانات مع cache و invalidation |
| حالة الواجهة (نوافذ، تبويبات، تحديد) | حالة محلية في المكوّن |
| حالة النماذج | مكتبة نماذج مع تحقق من الـ schema |

**`FE-021` (MUST NOT):** ممنوع نسخ بيانات الخادم إلى مخزن عام ثم مزامنتها يدويًا. هذا مصدر لا ينضب لأخطاء «البيانات القديمة».

**`FE-022` (MUST):** الجلب والـ cache والإبطال عبر **طبقة واحدة موحّدة** في التطبيق كله.

**`FE-023` (MUST):** تمرير الخصائص العميق (prop drilling) المفرط يُحل بـ context أو تركيب أفضل — لا بمخزن عام لكل شيء.

**`FE-024` (MUST):** حالة المحرّر موثَّقة صراحةً (`VE-001`).

---

## 3. حالات الواجهة الإلزامية

**`FE-030` (MUST):** كل شاشة أساسية تعالج **أربع حالات** — لا واحدة:

| الحالة | المطلوب |
|---|---|
| **تحميل** | هيكل عظمي (skeleton) أو مؤشر واضح، بلا قفز في التخطيط |
| **فراغ** | شرح + إجراء مقترح، لا صفحة بيضاء |
| **خطأ** | سبب مفهوم + إعادة محاولة + طريق للدعم |
| **نجاح** | المحتوى |

**`FE-031` (MUST):** حدود الخطأ (Error Boundaries) على كل مسار رئيسي. خطأ في مكوّن واحد **لا يُظهر شاشة بيضاء** للتطبيق كله.

**`FE-032` (MUST):** أخطاء الخادم تُترجم لرسائل مفهومة عبر `error.code` (`API-022`)، لا عرض رسالة الخادم الخام.

**`FE-033` (MUST):** كل إجراء يغيّر حالة يعطي **تأكيدًا واضحًا**: نجاح أو فشل. الصمت بعد الضغط هو أسوأ رد.

**`FE-034` (MUST):** الأفعال المدمرة (حذف موقع، حذف حساب) تتطلب تأكيدًا صريحًا يذكر **ما سيُحذف بالضبط**، لا «هل أنت متأكد؟».

---

## 4. التفويض في الواجهة

**`FE-040` (MUST NOT):** **الواجهة لا تفرض صلاحيات** (`CORE-004`). تعرضها وتحسّن التجربة فقط.

**`FE-041` (MUST):** ما لا تسمح به الخطة يُعرض معطَّلًا **مع سبب وطريق للترقية** — لا مخفيًا ولا فاشلًا بصمت (`VE-060`).

**`FE-042` (MUST):** الواجهة تتعامل بلطف مع `403` من الخادم حتى لو ظنت أن الإجراء مسموح. الخادم هو المرجع.

---

## 5. الوصولية (Accessibility)

**`FE-050` (MUST):** HTML دلالي: `<button>` للأفعال، `<a>` للتنقل، عناوين `<h1>`–`<h6>` بترتيب منطقي، `<nav>`, `<main>`, `<footer>`.

**`FE-051` (MUST):** كل عنصر تفاعلي **قابل للوصول بلوحة المفاتيح**، مع مؤشر تركيز (focus) مرئي.

**`FE-052` (MUST):** كل حقل نموذج له `<label>` مرتبط فعليًا. `placeholder` **ليس** بديلًا عن `label`.

**`FE-053` (MUST):** تباين الألوان يحقق WCAG AA (4.5:1 للنص العادي، 3:1 للنص الكبير) — في لوحة التحكم وفي كل theme جاهز (`CE-033`).

**`FE-054` (MUST):** النوافذ المنبثقة تحبس التركيز، وتُغلق بـ `Escape`، وتعيد التركيز لمصدر الفتح.

**`FE-055` (MUST):** كل صورة لها `alt` مناسب (`CE-064`)، والصور الزخرفية `alt=""`.

**`FE-056` (MUST NOT):** ممنوع الاعتماد على اللون وحده لنقل معلومة.

---

## 6. RTL / LTR

**`FE-060` (MUST):** الاتجاه من **primitives** لا patches متفرقة (`IL-`). راجع [`23-i18n-rtl.md`](23-i18n-rtl.md).

**`FE-061` (MUST):** خصائص CSS منطقية دائمًا:

```css
/* ❌ ممنوع */  margin-left: 16px;  padding-right: 8px;  text-align: left;
/* ✅ صحيح */   margin-inline-start: 16px;  padding-inline-end: 8px;  text-align: start;
```

**`FE-062` (MUST):** الأيقونات الاتجاهية (أسهم، رجوع، تقدم) تنعكس في RTL؛ وغير الاتجاهية (بحث، إعدادات) لا تنعكس.

**`FE-063` (MUST):** كل شاشة تُختبر في RTL و LTR قبل الدمج (`CORE-DoD`).

---

## 7. الأداء

**`FE-070` (MUST):** المواقع المنشورة **أخف ما يمكن**: بلا JavaScript غير ضروري، بلا مكتبات ثقيلة، بلا خطوط زائدة.

> **لماذا:** زائر موقع العميل على شبكة موبايل بطيئة. كل كيلوبايت زائد يقلل فرصة تحويله — وهذا يضر عميلنا مباشرةً.

**`FE-071` (MUST):** الصور بأبعاد صريحة أو `aspect-ratio` لمنع قفز التخطيط (CLS).

**`FE-072` (MUST):** الخطوط: مجموعة محدودة، `font-display: swap`، وتحميل مسبق للحرِج منها.

**`FE-073` (MUST):** تقسيم الحزم (code splitting) على مستوى المسار في لوحة التحكم.

**`FE-074` (MUST):** ميزانية حجم للحزم مراقَبة في CI. تجاوزها يفشل الـ build أو يطلق تحذيرًا صريحًا.

**`FE-075` (MUST NOT):** ممنوع إضافة مكتبة ثقيلة لحل بسيط (`CORE-002`).

---

## 8. النماذج

**`FE-080` (MUST):** التحقق في الواجهة من **نفس schema** الخادم (`packages/schemas`) — تجربة أفضل، وليس بديلًا عن تحقق الخادم.

**`FE-081` (MUST):** أخطاء الحقول تُعرض **بجانب الحقل** لا في قائمة عامة أعلى الصفحة.

**`FE-082` (MUST):** الحماية من الإرسال المزدوج: تعطيل الزر أثناء الإرسال + منع التكرار.

**`FE-083` (MUST):** حالة «قيد الإرسال» واضحة، والفشل لا يفقد ما كتبه المستخدم.

## 9. الأنماط الممنوعة

| # | النمط | لماذا هو خطر |
|---|---|---|
| 1 | استيراد بين حزمتي الواجهة | كود لوحة التحكم يُشحن للزوار |
| 2 | أنواع API مكتوبة يدويًا | انحراف صامت يكسر الإنتاج |
| 3 | نسخ بيانات الخادم لمخزن عام | «بيانات قديمة» مزمنة |
| 4 | شاشة بلا حالة خطأ أو فراغ | تجربة مكسورة |
| 5 | بلا Error Boundary | شاشة بيضاء من خطأ واحد |
| 6 | عرض رسالة الخادم الخام | نص غير مفهوم أو تسريب |
| 7 | إخفاء زر كوسيلة تفويض | الـ API مكشوف |
| 8 | `<div onClick>` بدل `<button>` | غير قابل للوصول بلوحة المفاتيح |
| 9 | `placeholder` بدل `label` | يختفي عند الكتابة + غير مقروء للقارئ الصوتي |
| 10 | `margin-left` بدل المنطقي | تخطيط مكسور في RTL |
| 11 | صورة بلا أبعاد | قفز تخطيط يضر التجربة والـ SEO |
| 12 | مكتبة ثقيلة في موقع منشور | تحميل بطيء = تحويل أقل |
| 13 | بلا حماية من الإرسال المزدوج | leads أو عمليات مكررة |
| 14 | تأكيد «هل أنت متأكد؟» بلا تفاصيل | حذف بالخطأ |

## 10. الاختبارات المطلوبة

**`FE-090` (MUST):** اختبار لكل شاشة أساسية في حالاتها الأربع.

**`FE-091` (MUST):** اختبار وصولية آلي (axe أو ما يعادله) على كل شاشة رئيسية في CI.

**`FE-092` (MUST):** اختبار التنقل بلوحة المفاتيح للمسارات الحرجة.

**`FE-093` (MUST):** اختبار انحدار بصري في RTL و LTR على نقاط توقف متعددة.

**`FE-094` (MUST):** اختبار ميزانية الحزم في CI.

**`FE-095` (MUST):** اختبار معالجة `403`: الواجهة لا تنهار ولا تعرض خطأ تقنيًا.

---

## 11. Definition of Done — Frontend

- [ ] `strict: true`، بلا `any` وبلا `@ts-ignore`.
- [ ] أنواع الـ API من `packages/schemas`.
- [ ] لا استيراد بين حزمتي الواجهة.
- [ ] حالة الخادم عبر طبقة الجلب الموحّدة.
- [ ] الحالات الأربع معالَجة.
- [ ] Error Boundary على المسار.
- [ ] الأخطاء مترجَمة عبر `error.code`.
- [ ] الأفعال المدمرة بتأكيد يذكر التفاصيل.
- [ ] الحدود معروضة بسبب وطريق ترقية.
- [ ] HTML دلالي + تنقل كامل بلوحة المفاتيح + تركيز مرئي.
- [ ] `label` لكل حقل، وتباين WCAG AA.
- [ ] خصائص CSS منطقية فقط.
- [ ] مختبَر في RTL و LTR.
- [ ] صور بأبعاد، وخطوط محدودة بـ `swap`.
- [ ] ميزانية الحزم ضمن الحد.
- [ ] حماية من الإرسال المزدوج.
- [ ] اختبار الوصولية الآلي أخضر.

---

## 12. ما يحتاج ADR

- تغيير إطار العمل أو مكتبة الحالة الأساسية.
- إضافة مكتبة UI ثقيلة.
- تغيير استراتيجية العرض في لوحة التحكم.
- دمج حزمتي الواجهة.
- خفض أي متطلب وصولية.
